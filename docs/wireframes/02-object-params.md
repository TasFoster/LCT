# Макет: шаг 2 «Параметры объекта» (склад)

Черновой вайрфрейм — только расположение блоков и поведение, не дизайн.
Маршрут: `/projects/:id/wizard/params`. Данные: `ProjectInput.params`
(`WarehouseParams` / `AirportParams` / `MedicalParams`, контракт
[project_input.md](../../contracts/project_input.md)).

Базовое разрешение — **1366×768**. Живой макет: `/wireframes/params` в
приложении (`frontend`), он же ограничен рамкой 1366×768.

## Сетка при 1366×768

| Блок | Размер |
|---|---|
| Шапка приложения | 1366 × 56 |
| Шапка проекта | 1366 × 48 |
| Степпер (8 шагов) | 1366 × 48 |
| Рабочая область | 1366 × 552 |
| Нижняя панель (зафиксирована) | 1366 × 64 |

Рабочая область по горизонтали: поля 24 + **навигация по разделам 240** +
24 + **форма 710** (две колонки по 343) + 24 + **боковая панель 320** + 24.
Прокручивается **только колонка формы**, навигация и боковая панель
зафиксированы — при 768 px пользователь всегда видит, сколько осталось
заполнить, и не теряет кнопку «Далее».

## Блоки

**1. Навигация по разделам (240 px, зафиксирована).**
Разделы формы с индикатором заполнения `заполнено/всего`:

| Раздел | Поля `WarehouseParams` |
|---|---|
| Помещение | `area_sqm`, `available_area_sqm`, `working_zones`, `storage_type`, `layout_constraints`, `route_length_m` |
| Режим и объём операций | `operating_mode`, `inbound_ops_per_day`, `internal_ops_per_day`, `outbound_ops_per_day`, `current_throughput_per_hour` |
| Груз | `unit_load_weight_kg`, `unit_load_dimensions_mm`, `sku_count` |
| Персонал | `staff_count`, `staff_cost_per_month` |

Ниже — общий прогресс и счётчик ошибок со ссылкой «Перейти к ней» (скролл
к первому невалидному полю + фокус). Клик по разделу — скролл, не смена
страницы: форма остаётся одной, чтобы валидация была сквозной.

**2. Колонка формы (710 px, прокручивается).**
Заголовок, строка «Заполните N обязательных полей», кнопка импорта из
Excel/CSV (`ProjectInput.source = excel_import | csv_import`). Дальше —
секции с полями в две колонки; поля, которым нужна ширина (габариты,
списки, ограничения планировки), занимают обе.

**3. Боковая панель (320 px, зафиксирована).**
Верх — контекстная подсказка для поля в фокусе (по умолчанию — подсказка
раздела). Низ — блок «Что дальше»: на что именно влияют введённые числа при
подборе. Это и есть ответ на НФТ «понятно без инструкции»: не всплывающие
тултипы по наведению, а всегда видимый текст.

## Правила ввода и валидации

Для каждого типа объекта форма строится из **описания полей** (тип, единица,
диапазон, подсказка, зависимости) — один компонент `ObjectParamsForm` и три
описания, а не три свёрстанные формы. Новый `ObjectType` = новое описание.

| Правило | Как выглядит |
|---|---|
| Единицы измерения | всегда справа внутри поля (`м²`, `кг`, `мм`, `оп./сутки`, `₽/мес`), не в подписи — подпись остаётся короткой |
| Обязательность | `*` у подписи; список незаполненных — в левой навигации |
| Валидация | по потере фокуса, повторная — на «Далее»; ошибка под полем текстом, что не так и что сделать |
| Диапазоны | мягкие: значение вне типичного диапазона — не ошибка, а предупреждение «необычно много для площади 5 000 м², проверьте» |
| Числа | разделитель разрядов пробелом при потере фокуса (`1 200`), ввод — свободный |
| Габариты | маска `Д×Ш×В` в мм, в `unit_load_dimensions_mm` уходит строкой (как в контракте) |
| Списки (`working_zones`, `layout_constraints`) | мультиселект из справочника + «Добавить своё» |
| Зависимость | `available_area_sqm` не больше `area_sqm` — иначе предупреждение |
| Автосохранение | debounce 2 с, отметка времени в шапке проекта |
| «Далее» неактивна | рядом причина: «Заполните 4 обязательных поля» — не молчащая серая кнопка |

## Отличия для других типов объектов

Меняется только состав разделов, каркас остаётся:
- **Аэропорт** (`AirportParams`): «Зона и режим» (`operation_zone`,
  `operating_mode`, `zone_access`), «Потоки» (`passenger_flow_per_day`,
  `cargo_flow_tons_per_day`, `ops_count_per_day`, `peak_load_per_hour`),
  «Груз и маршруты», «Персонал», «Безопасность» (`safety_requirements`).
  Пассажиропоток и грузопоток необязательны, но **должен быть заполнен хотя
  бы один** — иначе подбор не на чем строить.
- **Медучреждение** (`MedicalParams`): «Учреждение» (`facility_type`,
  `area_sqm`, `floors_count`, `operating_mode`), «Потоки грузов»
  (`cargo_volume_per_day` — таблица по категориям: грузы / бельё / питание /
  медикаменты / отходы), «Маршруты и лифты», «Персонал», «Санитария и
  доступ».

## Открытые вопросы

1. Справочники (режимы работы, типы хранения, зоны, ограничения планировки)
   — отдельная ручка каталога или зашиваем на фронте до появления `/admin/dictionaries`?
2. Импорт Excel/CSV — разбираем на фронте или отправляем файл на бэкенд?
   Контракт помечает источник (`source`), но формат шаблона не описан.
3. Нужен ли «быстрый режим» (5 ключевых полей, остальное по умолчанию) для
   демо-расчёта гостя — иначе 17 полей до первого результата.

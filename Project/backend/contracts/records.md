# records.py — контракт 9: ProjectRecord

Граница: **Владимиров (backend-glue) ↔ БД, → фронт**. Версионирование по
снапшотам: воспроизводимость расчёта (п. 4.3.4 ТЗ) означает «открыл старую
версию — увидел те же входные данные и тот же результат», а не пересчёт по
текущим формулам/каталогу.

## ProjectVersion
| Поле | Тип | Обязательное/по умолчанию | Описание |
|---|---|---|---|
| version | int | да | Номер версии |
| created_at | datetime | да | Момент создания версии |
| project_input | ProjectInput | да | Снапшот входных параметров объекта |
| topology | TopologyConfig \| null | null | Снапшот сцены (если создавалась) |
| match_result | MatchResult \| null | null | Снапшот результата подбора (если выполнялся) |
| scenarios | list[EconomicsResult] | [] | Снапшоты рассчитанных сценариев — минимум 3 по ТЗ |

## ProjectRecord (корневая модель)
| Поле | Тип | Обязательное/по умолчанию | Описание |
|---|---|---|---|
| id | str | да | Идентификатор проекта |
| owner_user_id | str | да | Владелец проекта (для изоляции между пользователями) |
| name | str | да | Название проекта |
| object_type | ObjectType | да | Тип объекта |
| status | ProjectStatus | `draft` | `draft` / `calculated` / `archived` |
| created_at | datetime | да | Дата создания проекта |
| updated_at | datetime | да | Дата последнего обновления |
| current_version | int | `1` | Номер текущей активной версии |
| versions | list[ProjectVersion] | [] | История версий для повторного воспроизведения расчёта |
